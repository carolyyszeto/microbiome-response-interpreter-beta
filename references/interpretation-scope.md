# Interpretation Scope

## Allowed

The skill may support:

- data-readiness assessment
- conservative workflow recommendation
- descriptive compositional summaries
- paired microbiome response summaries when the data truly support pairing
- restrained language about displacement, coherence, structure, and compositional differences
- methods and results wording that stays non-clinical and non-predictive

## Allowed With Caution

- discussion of ordination structure when the inputs support it
- directional or geometry-aware language when CLR/Aitchison or another justified compositional framework is available
- distance-based fallback interpretation when clearly labeled as a fallback rather than the preferred route

## Not Allowed

The skill must not produce:

- responder prediction
- individualized recommendation
- treatment recommendation
- customer-facing product claims
- clinical advice
- outcome-model branches from the audited gold-trial scripts
- manuscript figure assembly or figure-polish workflows
- study-local report generation

## Safe Language Pattern

Prefer language such as:

- "the dataset supports"
- "the data are consistent with"
- "paired compositional analysis suggests"
- "this remains descriptive"
- "this does not establish clinical effect or prediction"
- "the readable summary reflects the backend tables and should be read as a descriptive note"

Avoid language such as:

- "responders can be predicted"
- "the microbiome indicates treatment success"
- "this supports clinical recommendation"
- "customers should be classified"
- "this report recommends"
- "the figure demonstrates efficacy"

## If The User Pushes Past Scope

If the user asks for excluded outputs:

1. state the scope boundary directly
2. explain what the current skill can still support
3. offer a descriptive or methodological alternative
